superpowers: 요청 하나가 끝날 때까지

v6.3.0 설치본 원문 기준. 마스터(컨트롤러)는 메인 세션이고 직접 구현하지 않는다. 근거: studies/superpowers.md
사람 에이전트(LLM) 스크립트, 규칙 파일(설계, 계획, 보고) 장부

상태는 파일에 (압축돼도 남음)

장부 progress.md계획마다 하나. 첫 줄에 어느 계획인지. 태스크 완료, 수정 라운드, 결정(Ruling), 미뤄둔 사소한 지적
task-N-brief.md태스크 요구사항의 유일한 원본. 지시문엔 경로만
task-N-report.md구현자의 전체 보고와 테스트 증거. 컨트롤러에겐 15줄만
리뷰 패키지커밋 목록 + 변경 요약 + diff 전체를 파일 하나로
장부 없이 위치를 잃은 컨트롤러가 끝난 태스크를 통째로 다시 돌린 것이 관찰된 가장 비싼 실패

4. SDD: 컨트롤러가 태스크마다 반복

착수 전 모순 검사태스크 쌍마다 표로 기록
→
구현자 (새 에이전트)brief 읽고, 테스트, 커밋, 자기 리뷰. 하위 에이전트 금지. 모델 명시 필수
→
태스크 리뷰어 (새 에이전트)명세 준수 + 품질 둘 다 판정. 보고를 믿지 않음
수정 차단기1~3라운드 같은 구현자, 4~5라운드 강한 모델 새 구현자, 이후 컨트롤러가 판정해 장부에 기록
장부에 완료 기록커밋 범위, 리뷰 결과
↻ 다음 태스크. 컨트롤러는 직접 고치지 않음
↓
최종 브랜치 전체 리뷰 (가장 강한 모델)지적이 있으면 수정 에이전트 1개, 재리뷰 1번. 두 번째 수정 물결 없음
↓
5. 사람이 고름: 병합 / PR / 보관 / 폐기함께 "내가 대신 내린 결정" 전체 목록(틀렸을 때 비용 포함)

실행 중 사람에게 묻는 건 4가지뿐

멈추고 묻는다1. 되돌릴 수 없거나 파괴적인 행동
2. 보안에 민감한 행동
3. 작업 공간 밖 영향(병합, 공유 브랜치 push, 게시)
4. 모든 길이 추측뿐인 망가진 계획
그 외는 결정하고 기록장부에 "결정 / 이유 / 틀렸을 때 비용"
도입 배경: 스스로 정할 수 있던 질문 하나에 한 세션이 거의 9시간 멈춤(#2077)

비용 규칙

역할별 모델받아쓰기형 구현은 가장 싼 모델, 통합은 표준, 설계와 최종 리뷰는 가장 강한 모델
리뷰는 싼 모델 금지haiku 리뷰어: 심어둔 결함 10개 중 0개를 올바른 심각도로 지적
지시문에 이전 이력을 붙이지 않음(4.2만 자 중 99%가 이력이던 사례)
