## 핵심 한 문장
re:Invent 2024 금융 세션에서 소개된 세 회사의 생성형 AI 사례를 요약한 글로, 공통 교훈은 "AI 초안, 사람의 판단, 고객 피드백, 프롬프트/RAG 개선"을 반복하는 GenAIOps(FMOps) 루프와, Crypto.com의 멀티 에이전트 합의(리더 모델 지정, 불일치 시 우선순위 규칙, 합의 결과로 리더 재학습)이다.

## 배경과 문제 (AWS 발표 요약)
- AWS Generative AI Stack 3계층: 애플리케이션 계층, 도구 계층(LLM/FM 연동), 인프라 계층(GPU, Trainium, SageMaker, Neuron).
- 브릿지워터: 50여 년 리서치 헤지펀드. 2024-09-23 약 3조 원 규모 AI 기반 펀드 출시. 금융 리서치 사이클에 AI 접목.
- MUFG: 고객마다 수백~수천 쪽 문서를 며칠 읽고 상품을 결정하는 고된 작업. 2026년까지 온라인 중소기업 대출 3배, 하루 만에 최대 1,000만 엔 대출 목표(2024년 3월 기사 인용). 금융 문서의 표 같은 비정형 데이터는 기존 AI 모델로는 학습 데이터 부족으로 활용 어려움.
- Crypto.com: 회원 1억 명 이상, 임직원 4천 명. 암호화폐 시세가 뉴스, SNS 감정에 민감. 90개국 25개 언어 서비스.

## 구조와 구성요소 (AWS 발표 요약)
- 브릿지워터 AIA Labs: 경제지표를 LLM에 넣어 인과관계 맵(Causal Map) 생성 후 시스템 분석. 슬라이드 키워드 "Grounded in causal relationships, Diagnosable, Self-improving". 사이클 Perceive → Hypothesize → Investigate → Synthesize → Learn, 가운데 Reasoning engine(Corpus of text → Pure text(LLM) → Causal map, Market history → Tabular model → Explain function)과 Compound memory. 인프라는 Bedrock, EKS 기반. [저자 해석] Textract OCR로 비정형 문서를 활용했을 것으로 보임.
- MUFG 금융 분석 서비스: 회사명, 분석 타입(기업 개별, 경쟁사, 금융 이슈), 장부 타입(대차대조표, 손익계산서, 현금흐름표) 입력 → 리포트 생성. 대화형 UI. 아키텍처: Web app → Cognito, ALB → ECS(React/Next.js) → API Gateway → Lambda → Bedrock, 데이터는 DynamoDB, S3, Engineer가 SageMaker Notebook으로 분석/학습. 모델은 Claude 3.5 Sonnet, Batch 추론(On-demand보다 저렴하고 안정적).
- Crypto.com 감정 분석: 뉴스를 영어로 번역 전처리(Bedrock Converse API로 여러 모델을 테스트해 번역 모델 선정) → 멀티 에이전트 3개 병렬 분석.
  - Bedrock Claude 3 Haiku(새 모델 적용이 쉬움)
  - SageMaker fine-tuned Llama 3 8B(리더)
  - 3rd party GPT(참조용)
  - 출력 형식: {"token":"btc", "sentiment":"bullish"}. 프롬프트 규칙: 암호화폐 관련이면 감정 분석, 강세/약세/중립 추출, 특정 코인이 없으면 빈 JSON 배열.

## 절차와 규칙 (AWS 발표 요약)
- MUFG GenAIOps 반복 과정(그림 8):
  1. AI draft: 기본 프롬프트로 초안 생성, 재무 수치, 문서, 내부 문서 조회
  2. Human judge: 사람이 발표 자료를 수동 조정, 최신 인사이트와 규제 반영
  3. Client feedback: 긍정/부정 피드백을 상황과 함께 저장
  4. AI upgrade: 피드백 기반으로 프롬프트와 RAG 인덱싱 조정
  5. GenAIOps: 자동 업데이트와 개선
  - 영업 직원이 입력한 프롬프트와 피드백으로 AI 개선. 현재는 SageMaker 단계에 사람 개입이 필요하지만 "가능한 한 빨리 자동화를 하는 것이 목표".
  - 데이터 추출 정확도를 높이려고 관계없는 데이터 태그 제거 튜닝을 반복.
- Crypto.com 멀티 에이전트 합의(그림 13):
  1. Input: 영어로 요약된 뉴스
  2. Analysis x 3: 세 모델 병렬 분석
  3a. Reach consensus: 전원 합의 시 Best confidence로 즉시 Dataset 저장
  3b. Diverged: 우선순위 1st 신뢰도 낮은 뉴스 필터, 2nd 다수결, 3rd 리더 결과 채택 → Better confidence로 저장
  4. Store: Dataset
  5. Fine-tune model in batch and re-deploy: 저장된 데이터로 리더 모델을 배치 재학습 후 재배포
- 향후 계획: 시장 데이터와 뉴스 감정을 결합해 RAG 지식 베이스로 삼아 고객 Q&A에 활용.

## 수치와 결과 (모두 AWS 발표 내용)
- 브릿지워터: 인과관계 맵 생성 10초, 키워드 4개 요약. AI 펀드 약 3조 원.
- MUFG: 데이터 추출 정확도 최대 90% 정도, 숙련 직원이 며칠 걸리던 작업을 1~2분, 개발 기간 3개월 이상, 개발 중에도 서비스 제공, 생성률 10배 증가, 상품 판매 전환율 30% 이상 유지.
- Crypto.com: 정확도 90% 이상, 멀티 에이전트 구조로 6주 만에 달성 및 서비스 오픈.
- 세 발표자 공통: 업무 효율 최대 10배 증가.
- 카카오페이 자체 수치는 원문에 없음.

## 실패, 한계, 주의점
- MUFG: 기존 AI 모델은 학습 데이터 부족으로 비정형 데이터 처리 실패, 그래서 LLM 도입. 사람 개입 단계가 아직 남아 있음.
- 마치며(저자 정리): 금융에서는 높은 정확도가 필요하고 환각과 허위 정보를 최소화해야 하며, 발표자들이 핵심으로 짚은 것은 "체계적이고 반복적인 AI 개발 과정"과 실제 고객 피드백 반복.
- 사례별 실패, 롤백 경험은 원문에 없음.

## 우리 설계에 쓸 만한 점
- [추론] 이 글의 내용은 카카오페이 실무가 아니라 AWS 발표 요약이므로, 우리 설계 문서에서 "카카오페이 방식"으로 인용하면 안 된다. 출처를 "re:Invent 2024 금융 세션(카카오페이 블로그 요약)"으로 표기할 것.
- [추론] Crypto.com 합의 흐름은 멀티 에이전트 점검(inspection) 설계에 직접 쓸 수 있다: 서로 다른 모델 3개가 병렬 판정 → 전원 일치면 통과 → 불일치면 저신뢰 입력 필터, 다수결, 리더 판정 순 → 결과를 데이터셋으로 쌓아 리더 개선. 운영 부서의 검수 에이전트 구성 후보.
- [추론] "불일치 = 저신뢰" 신호를 사람 검토 큐로 보내는 변형도 가능하다(원문은 자동 우선순위로 처리). 금융이나 대외 게시처럼 위험이 크면 불일치 건은 사람 승인으로 돌리는 편이 안전하다.
- [추론] MUFG 5단계(AI 초안 → 사람 판단 → 고객 피드백 저장 → 프롬프트/RAG 조정 → 자동 개선)는 마케팅 부서 콘텐츠 생산 루프의 기본형으로 쓸 수 있다. 사람 판단 단계에서 "최신 규제 반영"을 명시한 점은 금융, 광고 심의 체크포인트와 연결된다.
- [추론] 피드백을 "상황과 함께 저장"하는 것이 핵심 설계 요소다. 운영 부서는 승인/반려 사유와 맥락을 구조화해 저장해야 다음 개선 입력이 된다.
- [추론] 입력 정규화(다국어를 영어로 번역) 같은 전처리 단계를 별도 에이전트로 분리하고 모델 비교로 선택한 방식은, 파이프라인의 각 단계를 교체 가능한 부품으로 두는 설계 근거가 된다.
- [추론] "사람 개입을 가능한 빨리 자동화" 목표와 "금융은 정확도와 환각 최소화가 필수"라는 결론이 공존한다. 자동화 확대는 정확도 지표가 기준을 넘은 단계에서만 하도록 롤아웃 조건을 정해 둘 것.
