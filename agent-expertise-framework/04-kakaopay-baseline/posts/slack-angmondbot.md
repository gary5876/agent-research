# 사내 기술 공유 슬랙봇 앙몬드 개발기

- URL: https://tech.kakaopay.com/post/slack-angmondbot/
- 게시일: 2024-08-22 (페이지 표기상 수정일 2026-03-24)
- 저자: lets.go (레츠), 공동 개발자 가디(gady.garden)
- 태그: 슬랙봇, FE
- 소속: 카카오페이 마이데이터클랜 FE 개발 (저자 소개상 "자산관리 서비스의 FE 개발")

## 핵심 한 문장
FE 기술 공유 채널의 글을 매주 사람이 복붙해 사내 게시판에 올리던 일을 슬랙 API와 크론잡으로 자동화하고, TIL 기록, 잔디, 명예의 전당, 보관함 같은 참여 장치를 붙여 기술 공유를 쉽고 재미있게 만든 사내 사이드 프로젝트 슬랙봇.

## 배경과 문제
- FE 개발자들은 #정보-fe기술공유 채널에서 아티클과 꿀팁을 공유하고, 이를 한 주 단위로 모아 "FE 위클리 아카이브"로 사내 게시판에 업로드한다.
- 초기에는 FE 개발자 한 명이 매주 수기로 업로드. "단순 복붙 작업임에도 시간이 꽤나 걸리는 번거로운 작업".
- 주니어는 "이미 다들 알고 있는 내용일 것 같은데" 하며 공유를 망설임.

## 구조와 구성요소
- 앙몬드 슬랙봇(FE 개발자 2명이 기획, 디자인, 서버 개발, 배포까지 진행한 사이드 프로젝트). 서버 스택 세부는 2편 참고(TypeORM, Redis, k8s 2개 리전).
- 기능:
  1. FE 위클리 아카이브 자동 게시: 슬랙 API + 크론잡, 매주 월요일 오전 9시.
  2. TIL 기록/공유: 홈 "오늘 배운 것" 탭.
  3. TIL 잔디: 월별 잔디 그리드. TIL 작성과 기술 공유 채널 게시 시 자동으로 채워짐.
  4. 명예의 전당: 위클리 아카이브 글 하단. 이번 주 최다 공유자, 리액션 부자, 인기글 Top 3.
  5. 보관함: "내 보관함에 추가하기" shortcut으로 나중에 볼 기술 공유 메시지 저장(유저 의견 반영 기능).
- 사용 API: conversations.history(채널 메시지), reactions.get(이모지 종류와 남긴 유저), users.info(유저 ID를 이름으로).
- UI: Slack Block Kit. 탭은 버튼 여러 개로 구현(선택 여부는 버튼 타입으로 구분, 선택 탭 상태는 유저별 관리). 잔디는 피그마로 만든 커스텀 이모지(:commit_3: 등)로 표현.

## 절차와 규칙
- TIL 기록 흐름: 홈에서 "배운 내용 기록하기" 클릭 → 앙몬드가 TIL 작성 스레드 생성 → 스레드에 채팅으로 입력 후 "작성완료" → 잔디 채워지고 "오늘 배운 내용들"에 표시 → "공유하기"로 #정보-fe기술공유에 바로 게시.
- 입력 방식 선택: 모달, 워크플로우 등을 직접 구현, 테스트한 뒤 코드블록 마크다운 지원과 "작성 중에 잠시 다른 채널로 이동해도 내용이 유지되는" 채팅 형식을 택함.
- 기술 공유로 잔디가 채워지면 유저에게 "방금 공유한 글로 잔디를 심었어요" 후킹 메시지 발송.
- 슬랙 메시지를 사내 게시판 마크다운으로 옮길 때 5단계 포맷팅:
  1. HTML entities 디코딩(&lt;, &gt; 등)
  2. 슬랙 이모지 제거(universal-emoji-parser 같은 라이브러리는 오매핑이 많고 커스텀 이모지 대응 불가라 전부 제거로 결정)
  3. 유저 멘션 텍스트 변환(@U12ABCD3EFG 같은 ID를 users.info로 이름으로 치환)
  4. 슬랙 링크 포맷을 마크다운 링크로 변환
  5. 코드 블록 시작과 끝에 줄 바꿈 추가

## 수치와 결과
- 위클리 아카이브 게시 시각: 매주 월요일 오전 9시.
- 포맷팅 단계 5개, 명예의 전당 통계 3개.
- 사용률, 절감 시간 등 정량 효과는 원문에 없음. 정성 서술로 "TIL 잔디는 역시나 앙몬드 출시 후 개발자들의 반응이 가장 뜨거웠던 기능", 사내 테크톡으로 알린 뒤 크루들이 잔디를 채우며 참여, #정보-be기술공유 채널에도 확대 적용.

## 실패, 한계, 주의점
- 방향성 없이 투두, 리마인더 등 기능을 넣으려다 우선순위를 못 정하고 의욕을 잃음. 역할을 "모두가 쉽게 기술 공유를 할 수 있도록 도움을 주는 기술 공유봇"으로 확정한 뒤 속도가 붙음.
- 가장 아쉬운 점은 빨리 릴리즈하지 않은 것. 기능 확신 부족과 기능 추가 욕심으로 출시가 늦어지고 프로젝트에 소홀해진 기간이 있었음.
- "배포만 남았다" 이후가 진짜 시작: 자체 QA, 에러/예외 케이스 처리, 사용자 가이드 작성, 처음 해보는 서버 배포(데브옵스, 서버 개발자 도움).
- 단순해 보인 conversations.history 기반 아카이빙이 포맷 차이로 "와장창" 깨짐.
- Block Kit은 기본 컴포넌트만 제공해 복잡한 UI에 한계.

## 그림 설명
- 그림 1: 앙몬드 캐릭터/소개 이미지로 보이는 도입부 이미지. 확인하지 않음(장식으로 판단).
- 그림 2: AS-IS/TO-BE 비교. AS-IS는 ben.lee가 2023년 8월 17일 수기로 올린 "Frontend Weekly Archive 30 (230807 ~ 230813)". TO-BE는 "Angmond (bot)"이 2024년 7월 22일(월) 09:00에 올린 "Frontend Weekly Archive (2024-07-15 ~ 2024-07-22)", 항목마다 "원본 글 보러가기 by @작성자" 링크 포함.
- 그림 3: 관심을 보인 크루 캡처(캡션 "앙몬드에 가장 먼저 관심 가져주신 폴!!"). 확인하지 않음.
- 그림 4: 홈 "오늘 배운 것" 탭. "오늘 2개의 지식을 기록했어요", 어제/오늘/날짜 선택, "배운 내용 기록하기" 버튼, 월간 잔디(Less~More 5단계 색), "오늘 배운 내용들" 목록과 항목별 "공유하기" 버튼.
- 그림 5: TIL을 공유한 예시 메시지("[Pylon 파이프라인]" TIL, 리액션 18 등). 공유 기능 결과 화면.
- 그림 6: 잔디 관련 이미지. 확인하지 않음.
- 그림 7: 봇 메시지 "방금 공유한 글로 잔디를 심었어요 / 홈화면을 확인해보세요."
- 그림 8: 잔디에 대한 크루 반응 캡처("저도 잔디 심기 동참할게요!", "슬프다 내 잔디!!!!").
- 그림 9: 명예의 전당 예시. 최다 공유자(@ben.lee 5개, 2개, 2개), 리액션 부자 3명, 인기글 top3.
- 그림 10~14: 명예의 전당 각 항목과 보관함 shortcut, 보관함 탭 UI 캡처. 확인하지 않음(본문 설명과 중복되는 UI 캡처).
- 그림 15: "슬랙 내용 복붙이니까 간단하겠군!" → "와장창": 코드 블록 깨짐(&lt;, &gt;), 슬랙 이모지 깨짐(:sadpepe:), 링크 깨짐(<url|text> 형태).
- 그림 16~18: HTML entities, 링크 포맷, 코드 블록 변환 전후 예시. 확인하지 않음.
- 그림 19: 피그마로 만든 28x28 잔디 이모지 5단계와 슬랙 커스텀 이모지(:commit_3:)로 그린 잔디 그리드.

## 우리 설계에 쓸 만한 점
- [추론] 주간 아카이브처럼 "정해진 시각에 모아서 게시"하는 일은 운영 부서의 정기 생산(production) 작업 유형으로 분류할 수 있다. 크론 트리거 + 수집 + 변환 + 게시의 4단계로 템플릿화 가능.
- [추론] 플랫폼 간 콘텐츠 이동 시 포맷 변환 규칙(엔티티, 멘션, 링크, 코드블록, 이모지)을 명시적 체크리스트로 두고, 게시 전 점검(inspection) 에이전트가 깨짐 여부를 검사하게 하면 좋다.
- [추론] 변환이 불확실한 요소(커스텀 이모지)는 억지로 매핑하지 않고 제거하는 보수적 규칙이 품질 사고를 줄인다. 에이전트 출력 정규화 원칙으로 쓸 만하다.
- [추론] 리액션 수, 공유 수 같은 반응 지표를 주간 리포트로 자동 집계하는 것은 마케팅 부서(사내 참여 유도)와 운영 부서(성과 측정)가 공유할 수 있는 피드백 루프 예시다.
- [추론] "역할 한 문장 확정 후 핵심 기능에 집중"과 "작게라도 먼저 릴리즈 후 피드백" 교훈은 각 부서 에이전트의 범위 정의와 점진 출시 원칙으로 옮길 수 있다.
- [추론] 이 봇에는 사람 승인 단계가 없다(게시가 저위험 사내 공지이기 때문). 위험도가 낮은 게시물은 완전 자동, 대외 게시물은 승인 필요처럼 위험도 기준으로 승인 경계를 나누는 참고 사례가 된다.
